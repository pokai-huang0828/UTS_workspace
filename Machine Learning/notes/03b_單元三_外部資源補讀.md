## 1. ⭐ 澳洲 AI 倫理原則（A2 倫理段落的首選引用）

**發布者**：Department of Industry, Science and Resources（澳洲產業、科學暨資源部）
**發布日**：2019-11-07 ｜**更新日**：2025-12-02
**性質**：⭐ **自願性（voluntary）**，非強制。

**目的**（原文）：
- 讓所有澳洲人獲得**更安全、更可靠、更公平的結果**
- **降低 AI 應用對受影響者造成負面衝擊的風險**
- 協助企業與政府在設計、開發、實施 AI 時**實踐最高的倫理標準**

### 八條原則（官方精簡版原文）

| # | 原則 | 官方定義 |
|---|---|---|
| 1 | **Human, societal and environmental wellbeing**<br>人類、社會與環境福祉 | AI 系統應**造福個人、社會與環境** |
| 2 | **Human-centred values**<br>以人為本的價值 | AI 系統應**尊重人權、多樣性與個人自主權** |
| 3 | **Fairness**<br>公平性 | AI 系統應**具包容性與可及性**，且**不應涉及或導致對個人、社群或群體的不公平歧視** |
| 4 | **Privacy protection and security**<br>隱私保護與安全 | AI 系統應**尊重並維護隱私權與資料保護**，並**確保資料安全** |
| 5 | **Reliability and safety**<br>可靠性與安全性 | AI 系統應**依其預期目的可靠地運作** |
| 6 | **Transparency and explainability**<br>透明度與可解釋性 | 應具備**透明度與負責任的揭露**，使人們能**了解自己何時受到 AI 重大影響**，並能**得知何時有 AI 系統正在與他們互動** |
| 7 | ⭐ **Contestability**<br>可申訴性 | 當 AI 系統對人、社群、群體或環境**造成重大影響**時，應有**及時的流程讓人們挑戰該 AI 系統的使用或其結果** |
| 8 | **Accountability**<br>問責制 | 負責 AI 系統生命週期各階段的人員應**可被識別並對結果負責**，且應**啟用對 AI 系統的人為監督** |

> 📌 **注意第 7 條「可申訴性（Contestability）」** —— 這一條**單元 1.6 與 3.2 都沒有列出**
> （課程的倫理五項是：偏差、透明度、隱私、公平性、問責制）。
> **澳洲官方多了「人類社會環境福祉」「以人為本價值」「可靠性與安全性」「可申訴性」四條。**
> 🎯 **A2 引這個能顯示你查了原始出處，而不是只抄課程頁面。**

### 幾條細節（值得引用的原文）

**公平性**：
> 「特別重要的是，AI 有可能**延續社會不公**，並對**弱勢與代表性不足的群體**產生不成比例的影響 ——
> 包括但不限於與**年齡、身心障礙、種族、性別、雙性狀態、性別認同、性傾向**相關的群體。
> **應採取措施確保 AI 產生的決策符合反歧視法。**」

> 🎯 **Bank X 直接對應**：資料裡有 `age`、`job`、`marital`、`education` —— **`age` 正好在清單上**。

**隱私保護與安全**：
> 「包括為 AI 系統使用與產生的所有資料確保**適當的資料治理與管理**，
> 例如透過**適當的資料匿名化（anonymisation）**維護隱私。
> 此外，**資料與 AI 從該資料所得推論之間的連結，應當合理並持續受到評估。**」

**透明度 —— 為什麼各利害關係人都需要它（原文列出七類）**：
| 對象 | 需要知道什麼 |
|---|---|
| 使用者 | 系統在做什麼、為什麼 |
| 建立者（含驗證與認證者） | 系統流程與輸入資料 |
| 部署與運營者 | 流程與輸入資料 |
| **事故調查員** | 若發生事故 |
| **監管機關** | 調查時 |
| **法律程序參與者** | 佐證與決策 |
| 公眾 | 建立對技術的信心 |

**可申訴性**：
> 「**知道『出錯時可以獲得補救』，是確保公眾信任 AI 的關鍵。應特別留意弱勢個人或群體。**
> 應有足夠的管道取得演算法可用的資訊與所作推論，才能讓申訴真正有效。
> 在**重大影響權利的決策**上，應有**有效的監督系統，並適當運用人為判斷**。」

## 2. ⭐ Google《Rules of Machine Learning》（3.1 的正課）

> Canvas 3.1 頁面只列了 4 條實踐，並說「參閱《機器學習規則》」。以下是原文的 43 條規則。
> 作者：Martin Zinkevich（Google）。Canvas 亦附有 PDF（file 13199299）。

### 階段零：在用機器學習之前

| # | 規則 |
|---|---|
| **1** | ⭐ **「不要害怕在沒有機器學習的情況下推出產品。」**<br>啟發式規則（heuristics）常常在需要 ML 之前就能帶來可觀的效益；避免過早引入複雜度 |
| **2** | ⭐ **「首先，設計並實作『指標』。」**<br>在建 ML 系統**之前**就全面追蹤系統行為；**盡早建立衡量基礎設施** |
| **3** | **「當啟發式規則變複雜時，選擇機器學習。」**<br>一旦有了資料且目標明確，**ML 比複雜的規則式方法更容易維護** |

> 🎯 **對應 Canvas 3.1 的第 1 條「從簡單模型開始」**，但原文其實更激進：**先別用 ML**。

### 階段一：你的第一條 Pipeline

| # | 規則 |
|---|---|
| **4** | ⭐ **「讓第一個模型保持簡單，並把基礎設施做對。」** —— 重點放在 pipeline 可靠性而非演算法精巧度 |
| **5** | **「把基礎設施與機器學習分開測試。」** |
| **6** | **「複製 pipeline 時，小心被丟掉的資料。」** |
| **7** | **「把啟發式規則轉成特徵，或在外部處理它們。」** —— 不要丟掉已驗證有效的領域知識 |
| **8** | **「了解你系統的『新鮮度』要求。」** —— 理解效能衰退的時間尺度，才能決定更新頻率 |
| **9** | **「在匯出模型之前偵測問題。」** |
| **10** | ⭐ **「留意『無聲的失敗』（silent failures）。」** —— 持續監控**資料陳舊**與**特徵覆蓋率**；**漸進的效能衰退常常沒被注意到** |
| **11** | **「為特徵欄位指定負責人並撰寫文件。」** |

### 階段一：你的第一個目標

| # | 規則 |
|---|---|
| **12** | **「不要過度糾結該直接最佳化哪個目標。」** |
| **13** | ⭐ **「為第一個目標選一個『簡單、可觀察、可歸因』的指標。」** —— 先最佳化**直接可觀察的使用者行為**（點擊、下載），而非間接代理指標 |
| **14** | ⭐ **「從『可解釋的模型』開始，除錯會更容易。」** —— **線性迴歸與邏輯迴歸**便於診斷；其**校準特性**支持信心驗證 |
| **15** | **「在政策層（policy layer）中把垃圾訊息過濾與品質排序分開。」** |

### 階段二：特徵工程

| # | 規則（摘要） |
|---|---|
| **16** | 「計畫要推出並持續迭代。」 |
| **17** | ⭐ **「先用『直接觀察到的、被回報的』特徵，而不是『學習得到的』特徵。」** |
| **18** | 「探索能跨情境泛化的內容特徵。」 |
| **19** | 「能用非常具體的特徵時就用。」 |
| **20** | 「以人類可理解的方式組合與修改既有特徵。」（離散化、交叉） |
| **21** | ⭐ **「線性模型中你能學到的特徵權重數量，大致與你的資料量成正比。」** |
| **22** | **「清掉不再使用的特徵。」** —— 減少技術債 |

### 階段二：人工分析與訓練—服務偏斜

| # | 規則（摘要） |
|---|---|
| **23** | ⭐ **「你不是典型的終端使用者。」** —— 避免確認偏誤；用群眾評估與線上實驗 |
| **24** | 「測量模型之間的差異（delta）。」 |
| **25** | ⭐ **「選模型時，『實用效益』勝過『預測能力』。」** —— 最佳化下游應用行為，而非模型的概似度指標 |
| **26** | 「在測得的錯誤中找模式，據此建立新特徵。」 |
| **27** | ⭐ **「試著把觀察到的不良行為量化。」** —— **「先測量，後最佳化」** |
| **28** | ⭐ **「短期行為相同，不代表長期行為相同。」** —— 要考慮**回饋迴路** |
| **29** | ⭐ **消除訓練—服務偏斜的最佳方法：把「服務時實際用到的特徵」存下來記錄，再拿去訓練** |
| **30** | **「對抽樣資料做重要性加權，不要任意丟棄！」** |
| **31** | 「訓練與服務時若都 join 同一張表，注意表的內容可能已經變了。」 |
| **32** | 「盡可能在訓練 pipeline 與服務 pipeline 之間重用程式碼。」 |
| **33** | ⭐ **「若模型用到 1/5 為止的資料，就用 1/6 之後的資料測試。」** —— **時間上要在後面**，才反映真實部署 |
| **34** | 「二元分類做過濾時，為了取得乾淨資料，可短期犧牲一點效能。」 |
| **35** | 「當心排序問題中固有的偏斜。」 |
| **36** | 「避免與『位置特徵』形成回饋迴路。」 |
| **37** | **「測量訓練／服務偏斜。」** |

### 階段三：成長趨緩、最佳化、精修與複雜模型

| # | 規則（摘要） |
|---|---|
| **38** | 「若問題出在『目標不一致』，別浪費時間做新特徵。」 |
| **39** | 「上線決策是長期產品目標的代理指標。」 |
| **40** | ⭐ **「保持集成模型簡單。」** —— 只組合基礎模型，不要在模型上再訓練模型 |
| **41** | ⭐ **「效能進入高原期時，去找『質上全新的資訊來源』，而不是精修既有訊號。」** |
| **42** | 「別預期多樣性、個人化、相關性與『熱門度』的相關性有你想的那麼高。」 |
| **43** | 「你的朋友在不同產品間傾向相同；你的興趣則不然。」 |

> 🎯 **A2 可直接引用的**：規則 1（先別用 ML）、規則 2（先做指標）、規則 4（第一個模型保持簡單）、
> 規則 14（從可解釋模型開始 —— **支撐 Bank X 選邏輯迴歸**）、規則 29（避免訓練—服務偏斜）。

## 3. CRISP-ML(Q) 原始論文（arXiv 2003.05155）

**完整標題**：*Towards CRISP-ML(Q): A Machine Learning Process Model with Quality Assurance Methodology*
**作者**：Stefan Studer, Thanh Binh Bui, Christian Drescher, Alexander Hanuschkin,
Ludwig Winkler, Steven Peters, Klaus-Robert Müller
**年份**：**2020**（2020-03-11 投稿，2021-02-24 修訂）

**摘要要點**：
- 提出涵蓋**六個階段**的 ML 生命週期框架 —— 從初始範圍界定到持續維護
- ⭐ **強調把「業務理解」與「資料理解」在前期合併**，
  因為「**資料可得性往往決定專案是否可行**」
- 納入**當代監控策略**，以因應**不斷變化環境中的模型衰退風險**
- 對**每一項生命週期任務**，都建議「**適合應對機器學習開發挑戰的品質保證方法論**」

**相對 CRISP-DM 的四項推進**：

| # | 推進 |
|---|---|
| 1 | **ML 專屬聚焦** —— 明確處理「機器學習專屬任務」與 ML 系統固有風險，而非傳統資料探勘 |
| 2 | **品質保證整合** —— **系統性地將每個開發階段與對應的品質保證實踐配對**，取材自「實務經驗與科學文獻」 |
| 3 | **監控與維護** —— 第六階段強調部署後的監督，承認「**變化環境中的模型衰退風險是明顯存在的**」 |
| 4 | **產業中立** —— 設計為跨領域適用、與應用無關的指引 |

> 🎯 **A2 引用格式（APA 7）建議**：
> Studer, S., Bui, T. B., Drescher, C., Hanuschkin, A., Winkler, L., Peters, S., & Müller, K.-R. (2021).
> *Towards CRISP-ML(Q): A machine learning process model with quality assurance methodology.*
> arXiv. https://arxiv.org/abs/2003.05155

## 5. Google：決策樹的過擬合與剪枝

> 這是單元 2.5.3.2 引用的來源，但與單元三的「模型評估」也相關。

### 過擬合問題
> 決策樹能「**完美分類訓練樣本**」，但在資料含噪聲時，面對新資料常會表現不佳。

### 預剪枝（Pre-pruning）—— 訓練「中」套用

| 技術 | 說明 |
|---|---|
| **最大深度**（Maximum Depth） | 「**防止決策樹生長超過某個最大深度，例如 10**」 |
| **每個葉節點的最少樣本數** | 「**樣本數少於某個門檻的葉節點，將不被考慮進行劃分**」。<br>原文以**最少樣本 2、5、10** 三組對照圖示範：**門檻越高，捕捉到的噪聲越少** |

### 後剪枝（Post-pruning）—— 訓練「後」套用

用**驗證資料集**選擇性移除分支：
> 「**如果移除某個分支能提升模型在驗證資料集上的品質，就移除該分支。**」

### 具體預設值（YDF 函式庫）

| 參數 | 預設 |
|---|---|
| 最少樣本數 | **5** |
| 用於剪枝的驗證比例 | **訓練資料的 10%**（設為 0.0 可停用） |

### 多準則做法
> 許多實務者**同時結合三種方法**，並常用**交叉驗證 + 超參數調校**在多個值上搜尋
> （例如 max depth ∈ {3, 5, 6, 7, 8, 9}）。

> 📌 **補齊了 `02_` §2.5.3.2 的細節** —— Canvas 只說「設定停止標準 vs 剪枝」，
> 這裡給了**具體參數與預設值**。
