### 2.2 `campaign` 就是目標組 / 對照組 ⭐

Canvas 題目說樣本分成 Target Group 與 Control Group。**資料裡的 `campaign` 欄位就是它**，只有 0 和 1 兩個值：

| campaign | 人數 | y=yes | y=no | **轉換率** |
|---|---|---|---|---|
| **0（對照組，沒收到優惠）** | 23,546 | 2,340 | 21,206 | **9.94%** |
| **1（目標組，收到優惠）** | 17,642 | 2,300 | 15,342 | **13.04%** |

> **優惠方案帶來的提升 = 13.04% − 9.94% = 3.10 個百分點**（相對提升約 31%）。
> 這個數字就是 A2「商業價值」與 A3「成功標準」可以直接引用的**基準值**。

整體 y=yes 佔比 **11.27%**（4,640 / 41,188）—— **類別不平衡**，A3 要處理。

### 2.3 🔴 兩個資料陷阱（重要，會決定成績）

#### 陷阱一：`duration` 是資料洩漏（data leakage）

```
campaign=0（對照組）：duration 全部 = 0      （23,546 列）
campaign=1（目標組）：duration 平均 256.7 秒
y=no  的平均 duration = 92.7 秒
y=yes 的平均 duration = 246.2 秒
```

兩個問題：
1. **`duration` 只有打完電話才知道** —— 拿它預測「要不要打這通電話」是**因果倒置**，模型分數會虛高但實務無用。這是 UCI bank-marketing 資料集的經典陷阱。
2. **對照組的 `duration` 結構性為 0** —— 模型會直接學成「duration=0 就是對照組」，等於偷看答案。

> ✅ **正確做法**：建模時**排除 `duration`**，或明確說明它只能用於事後分析。
> 💡 **這正是 rubric 加分點**：技術路徑「變數識別」佔 20 分，商業路徑「結果轉化為商業價值」佔 40 分 ——
> 主動指出並排除洩漏特徵，是能拉開差距的論述。

#### 陷阱二：缺失值不是隨機的

`contact` / `month` / `day_of_week` 缺失的 23,546 列，**完全等於 campaign=0 的那 23,546 列**。

原因很合理：**對照組根本沒被打電話，所以沒有聯絡方式、月份、星期幾**。

> ✅ **正確做法**：這不是「髒資料」，是**結構性缺失**。不能直接丟掉（會把整個對照組刪光），
> 也不能盲目補值。要在 A2「資料理解 / 資料工程」段落把這件事講清楚。

### 2.4 其他觀察

- `poutcome`（前次行銷結果）：nonexistent 35,563 / failure 4,252 / success 1,373
- `previous`（前次接觸次數）：0 佔 35,563 列 —— 絕大多數是首次接觸
- `cons.price.idx` / `cons.conf.idx` 是總體經濟指標（消費者物價 / 信心指數），各 26 個相異值

### 🔴 唯一的環境缺口：`ydata_profiling`

Bank X 的 Notebook 用到 **`ydata_profiling`**（自動產生資料剖析報告），**你目前沒裝**。
其餘套件（sklearn 1.4.2、xgboost 3.2.0、joblib 1.3.2、tensorflow 2.20.0）**全部已具備**。

⚠️ **不要直接 `pip install ydata-profiling`**：
它對 pandas / numpy / scipy 有嚴格版本上限，而你的環境**已經被 `pycaret 3.3.2` 鎖住那幾個套件**
（見 [`../../ENV.md`](../../ENV.md) 第 75 行）。硬裝可能連帶降版，弄壞 A2b 的環境。

**兩個安全做法**：
1. **開一個獨立 venv** 給這門課用（推薦）—— `python -m venv .venv-ml`，在裡面裝 ydata_profiling，VS Code 切 kernel 即可。
2. **跳過它** —— `ydata_profiling` 只是做 EDA 報告，用 `pandas.describe()` + seaborn 手動畫也能達成同樣目的，而且更能展現理解。

> 這個決定不急，等你確定選 Bank X 之後再處理。
