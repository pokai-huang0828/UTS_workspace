### 2.2 `campaign` 就是目標組 / 對照組 ⭐

Canvas 題目說樣本分成 Target Group 與 Control Group。**資料裡的 `campaign` 欄位就是它**，只有 0 和 1 兩個值：

| campaign | 人數 | y=yes | y=no | **轉換率** |
|---|---|---|---|---|
| **0（對照組，沒收到優惠）** | 23,546 | 2,340 | 21,206 | **9.94%** |
| **1（目標組，收到優惠）** | 17,642 | 2,300 | 15,342 | **13.04%** |

> **優惠方案帶來的提升 = 13.04% − 9.94% = 3.10 個百分點**（相對提升約 31%）。
> 這個數字就是 A2「商業價值」與 A3「成功標準」可以直接引用的**基準值**。

整體 y=yes 佔比 **11.27%**（4,640 / 41,188）—— **類別不平衡**，A3 要處理。

### 2.3 🔴 兩個資料陷阱（重要，會決定成績）

#### 陷阱一：`duration` 是資料洩漏（data leakage）

```
campaign=0（對照組）：duration 全部 = 0      （23,546 列）
campaign=1（目標組）：duration 平均 256.7 秒
y=no  的平均 duration = 92.7 秒
y=yes 的平均 duration = 246.2 秒
```

兩個問題：
1. **`duration` 只有打完電話才知道** —— 拿它預測「要不要打這通電話」是**因果倒置**，模型分數會虛高但實務無用。這是 UCI bank-marketing 資料集的經典陷阱。
2. **對照組的 `duration` 結構性為 0** —— 模型會直接學成「duration=0 就是對照組」，等於偷看答案。

> ⚠️ **修正（讀完 Notebook 後）**：上面第 1 點要講得更精確。
> 官方 Notebook **刻意保留 `duration`**，但不是拿它當「已知特徵」——
> 它在「客戶評分」段把 duration 分成 11 桶，**模擬「如果我們打算聊 N 秒」時的接受機率**，
> 再用「通話越短權重越高」加權成分數。也就是把 duration 當成**可控制的成本槓桿**，
> 用來同時最佳化轉換率與呼叫中心成本 —— 正好對應題目的兩個目標。
>
> ✅ **準確的論述**：
> - 拿 `duration` **直接當預測特徵** → 是洩漏，因果倒置
> - 把 `duration` **當成成本模擬的槓桿** → 是合理設計，官方就是這樣做的
> - **但上面第 2 點官方沒處理**：對照組的 duration 結構性全為 0，
>   模型會把「duration=0」學成「這是對照組」。這個交互作用是真的沒被處理。
>
> 💡 **這就是 rubric 加分點**：技術路徑「變數識別」20 分、商業路徑「未來改進」10 分 ——
> 能把「洩漏 vs 槓桿」的區分講清楚，並指出對照組 duration=0 的殘留問題，是能拉開差距的論述。
> 完整說明見 [`bank_x/_Notebook拆解.md`](bank_x/_Notebook拆解.md)。

#### 陷阱二：缺失值不是隨機的

`contact` / `month` / `day_of_week` 缺失的 23,546 列，**完全等於 campaign=0 的那 23,546 列**。

原因很合理：**對照組根本沒被打電話，所以沒有聯絡方式、月份、星期幾**。

> ✅ **正確做法**：這不是「髒資料」，是**結構性缺失**。不能直接丟掉（會把整個對照組刪光），
> 也不能盲目補值。要在 A2「資料理解 / 資料工程」段落把這件事講清楚。

### 2.4 其他觀察

## 5. 對「選哪個情境」的意義（實查後）

| | Bank X | 房仲 X |
|---|---|---|
| 資料大小 | 4.5 MB CSV，41,188 列 | 172 MB，7,000 張圖 |
| 訓練成本 | 秒～分鐘級（GridSearch 要等） | 需 GPU —— Colab 免費 GPU 可解 |
| 官方範例可參考 | 1 份（Example_3） | 2 份（Example_1、Example_2） |
| Notebook 規模 | 77 cell,填空 8 處(**商業路徑只需做 4 處**) | 45 cell,填空 7 處 |
| 環境缺口 | **無**（用 Colab，官方預設） | **無**（用 Colab，且有免費 GPU） |
| 課程何時教到 | **第 3 週** | 第 6 週 |
| 現成的「商業數字」 | ✅ **9.94% vs 13.04%，提升 3.1pp** 直接可用 | ❌ 要自己估（20 分鐘 × 5 萬套/月） |
| 可寫的深度論述 | ✅ duration「洩漏 vs 槓桿」+ 結構性缺失 + pipeline 重複欄位，三個明確加分點 | interior 類別混淆 |

> **實查後的判斷**：Bank X 的資料裡**已經內建一個可直接引用的商業基準值**（對照組 vs 目標組轉換率），

> 房仲那條的訓練成本靠 Colab 免費 GPU 可以解決，但**第 6 週才教 CNN、第 7 週就要交**的時序壓力解決不了。
