## R-升級 · 何時該升級模型(或收回主迴圈)

**判準(任一命中即升)**:①同一子任務已失敗 2 次且第二次沒有比第一次好(haiku 例外:錯 1 次即升,照 01 §3)②任務要在「兩個都對的選項」間取捨(權衡,非查證)③輸出會直接對外(客戶信/對外口徑)④牽涉 SSOT 裁決(兩份文件矛盾要定一版)。升級階梯照 [01](01-model-dispatch.md) §3。

- ✅ 正例:Codex 兩次驗證 timeout 後,不第三次原樣重跑,改拆小任務(= 換方法);若拆小仍失敗才升級處理。
- ❌ 反例:haiku 盤點漏了一個目錄,又原樣派 haiku 掃第二次、第三次 — 該做的是升 sonnet 或自己收回。

## R-完成 · 何時算「真的完成」

**判準:交付訊息必須包含驗證證據,四選一**:①命令輸出(exit code / gate 結果)②read-back 摘要(檔案重讀後的關鍵行)③diff/對賬數字(來源 N → 輸出 N)④第二意見結論(誰驗的+結果)。**沒有證據 = 不得使用「完成/已修復/沒問題」字眼**,只能寫「已改,待驗證」。

- ✅ 正例:「build.py --check exit 0 ×2、Codex V1–V3 全 CONFIRMED,merge 完成」— 有輸出、有第二意見。
- ❌ 反例:「檔案我已經更新好了,應該沒問題」— 無任何證據,若 render 壞了就是 P1 事故重演。

## R-問人 · 何時停下來問 Kenny(其餘一律自己決定並標註假設)

**判準(僅限這四類)**:①要花錢/對外送出/不可逆(寄信、發佈、刪除、動 main)②兩個合理方案分歧會改變後續所有工作(架構級選擇)③發現 Kenny 的指示互相矛盾(引用兩處原文再問)④憑證/權限只有他有。**其餘情況**:選預設、寫「⚠️假設:___,若錯請告知」、繼續做。

- ✅ 正例:審計說「不動檔案」、交付 B 說「重寫 CLAUDE.md」→ 引用兩句原文,一次問清,拿到裁決才動。
- ❌ 反例:「請問檔名要用 -v2 還是 -final?」— 這是有慣例可查的事(repo 現有命名),不該問。

## R-換路 · 什麼訊號代表方向錯了(該換路,不是再試一次)

**判準(任一命中就停手換路)**:①Kenny 打斷 ≥2 次且第二次語氣是重定向(「等等」「先不要」「重新來過」)②同一錯誤訊息連續出現 2 次且第二次的修法只是「再跑一次」③你發現自己在為第 3 個 edge case 打補丁而主結構沒變 ④驗證通過但 Kenny 說結果不是他要的(= 驗收條件理解錯,回頭重對目標,不是改實作)。

- ✅ 正例:「等等我們重新來過,你先告訴我你的流程應該是甚麼」→ 正確反應 = 停止產出,先給 3 行流程等確認(CLAUDE.md HC3)。
- ❌ 反例:watchdog 檢查 0 命中,反應是「把 regex 再放寬一點」— 真正問題是頁面架構整個換掉了,檢查目標要重選。

## R-回讀 · 引用使用者資料前的回讀(對付「你看錯了」類錯誤,audit P5)

**判準**:使用 Kenny 給的日期/ID/名稱/數字做後續動作前,第一句先回讀關鍵值:「收到,以 5/21 的內容為準」。他給的資料與 repo 現況矛盾時,指出矛盾再問,不默默選一邊。

- ✅ 正例:「不對,Fleet ID 已經是 Fleet Name 了」→ 之後每次引用先回讀「用 Fleet Name=XXX 查」。
- ❌ 反例:直接拿 5/18 的舊內容開工,做完才被抓「我發的是 5/21」。

## R-新開 · 何時建議開新 session / spawn task(audit P4,×4 實錘)

**判準(任一命中就主動建議,不要默默續做)**:①Kenny 說「這個我想自己用」「要分享」②新需求與本 session 主題無關且預估 >30 分鐘 ③本 session 已跨 3 個主題、context 明顯稀釋 ④要做的事適合背景長跑。

- ✅ 正例:「可以隨時 call 就 update jira 的 skill」出現在會議 ingest session 中 → 「這個適合開新 session 做,我先把需求記下來?」
- ❌ 反例:在同一 session 裡把掃信、建檔、審計、寫 skill 全部串完,最後一段品質下滑。

## R-漂移 · 工具/環境跟規則打架時怎麼辦(新增 2026-07-09)

**判準(任一命中)**:①照治理檔派工卻報 model/參數/授權錯誤 ②harness 的工具說明與治理檔寫法矛盾 ③規則引用的路徑/檔案不存在。**第一動作 = 實查**(重讀該工具當下的說明/schema、`ls` 該路徑)→ 更新 [01](01-model-dispatch.md) §0 或修正引用(附實查日期)→ 才繼續原任務。**禁止**:瞎猜參數重試、默默繞過然後留著壞規則害下一個 session。

- ✅ 正例:2026-07-09 發現 Workflow 需 ultracode 授權(01 v1 沒寫)→ 更新 01 §0 + 改用平行 Agent,原任務照做。
- ❌ 反例:Agent 派工報 model 名錯,就換一個沒查證過的名字再試三次 — 該做的是讀 schema 一次確定。

## R-品質底線 · 交付前 60 秒 checklist(照抄執行)

```text
□ HC1:list/table 前有空行?repo 檔跑過 build 看過 mirror?
□ HC2:列舉型 → 來源 N = 輸出 N?差額有解釋?
□ 數字抄寫:關鍵數字(閾值/日期/票號)與來源逐字對過?(650ms 不是 6.5s 這種)
□ 對外內容:過 HC5 三紅線(無 Jira key/firmware 版號/內部準確率;個資已 strip)?
□ 完成宣稱:有 R-完成 的四種證據之一?
□ 檔案落地:每個新檔 read-back 過?
```

## Harness 極限(誠實條款)

以上 rubric 補得了「執行品質」:拆解、驗證、對賬、格式。**補不了「品味與模糊判斷」**:對外語氣拿捏、政治敏感度、「這個案子值不值得做」。弱模型遇到這三類:

1. 先照 R-問人 ③④ 判斷是不是該直接問 Kenny;
2. 需要第二意見時的管道排序:**Codex(異家族,失誤模式不同)> fresh opus/fable agent(往上派,見 01 §2)> 明說「這題需要 Kenny/高階模型判斷」**;
3. 都不可用就誠實標註「品味判斷,未經人核」,不要硬給定稿。
