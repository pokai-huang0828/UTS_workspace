## 1. 2.1 思考與分享:教育機構資料庫(code name 版)

在教育機構的資料庫中,我會設計四個核心的**數據對象(data objects)**,用類似資料表 schema 的方式描述,每個屬性同時標注它的屬性類型:

```sql
-- 1. 學生
Student(
  student_id,        -- 標稱 nominal(唯一識別碼)
  full_name,         -- 標稱 nominal
  date_of_birth,     -- 數值 numeric(區間 interval)
  nationality,       -- 標稱 nominal
  degree_level,      -- 次序 ordinal(bachelor < master < phd)
  enrolment_year,    -- 數值 numeric(區間 interval)
  gpa,               -- 數值 numeric(比率 ratio)
  is_full_time,      -- 二元 binary(true / false)
  email              -- 標稱 nominal
)

-- 2. 教職員工
Staff(
  staff_id,          -- 標稱 nominal(唯一識別碼)
  full_name,         -- 標稱 nominal
  title,             -- 次序 ordinal(lecturer < senior_lecturer < assoc_prof < professor)
  department,        -- 標稱 nominal
  office_no,         -- 標稱 nominal
  hire_date,         -- 數值 numeric(區間 interval)
  employment_type    -- 標稱 nominal(full_time / part_time / casual)
)

-- 3. 課程
Course(
  course_code,       -- 標稱 nominal(唯一識別碼)
  course_name,       -- 標稱 nominal
  credit_points,     -- 數值 numeric(比率 ratio)
  semester,          -- 標稱 nominal
  delivery_mode,     -- 標稱 nominal(face_to_face / online / hybrid)
  taught_by          -- 外鍵 → Staff.staff_id
)

-- 4. 選課紀錄(關聯 Student 與 Course)
Enrolment(
  student_id,        -- 外鍵 → Student.student_id
  course_code,       -- 外鍵 → Course.course_code
  final_score,       -- 數值 numeric(比率 ratio,0–100)
  grade,             -- 次序 ordinal(F < P < C < D < HD)
  attendance_rate    -- 數值 numeric(比率 ratio,0–100%)
)
```

每個數據對象括號內的完整屬性列表,就是它的**屬性向量(attribute vector)**——例如一筆學生紀錄 `("12345678", "王小明", 1995-03-01, "Taiwan", "master", 2026, 3.7, true, "...")` 就是一個具體的特徵向量。

在預處理階段先標清楚每個欄位的屬性類型很重要,因為類型決定了後續處理方式:標稱屬性(如 `department`)要做編碼才能餵給模型;數值屬性(如 `gpa`)可以標準化;次序屬性(如 `grade`)雖有大小順序,卻不能直接當一般數值取平均。

## 2. 2.2.1 平均數/中位數/眾數/中程數

**計算答案**(27 筆,已程式驗算):平均數 = 809÷27 ≈ **30**;中位數 = **25**(第 14 個值);眾數 = **25 和 35**(雙眾數,各 4 次);中程數 = (13+70)÷2 = **41.5**。

**評論框反思(可直接貼)**:

算完這四個數字,最大的感想是:只看一個數字,很容易被誤導。

平均數約 30 歲,看起來「典型客戶就是 30 歲上下」,但這個值其實是被 70 歲的客戶拉高的——超過一半的客戶不到 25 歲。中程數 41.5 的問題更明顯,它完全由最大和最小兩個極端值決定,參考價值很低。

相較之下,中位數(25 歲)不受離群值影響,比較接近客戶的真實樣貌。

最有價值的是眾數有兩個:25 和 35。這代表客戶可能不是一群人,而是兩個群體——一群在 25 歲左右,另一群在 35 歲左右。如果只拿「平均 30 歲」做行銷,可能兩邊都打不中;分成兩個客群來設計策略會更有效。

另外有一個發現:樣本裡出現了 13、15、16 歲的「客戶」,但這是一家酿造公司,未成年人不應該出現在客戶名單裡——可能是輸入錯誤,或欄位定義不清。這也呼應了上一節的重點:計算統計量之前,要先檢查資料、確認每個屬性的合理取值範圍。

## 3. 2.2.2 討論區:中程數/Q1/Q3/IQR + 箱型圖

⚠️ **要附 Kenny 自己在 Anaconda/Jupyter 跑的箱型圖截圖**(老師點名要 Anaconda 輸出)。預期圖形:箱子 20.5–35、橘線 25、鬚 13–52、70 是上方圓圈(異常值)。

**貼文內容(可直接貼)**:

計算結果:中程數 = (13+70)/2 = **41.5**;Q1 = **20**、Q3 = **35**(把 27 筆資料以中位數切半,各取一半的中位數);IQR = 35 − 20 = **15**。

用經驗法則找異常值:上圍欄 = Q3 + 1.5×IQR = **57.5**,下圍欄 = −2.5。只有 **70 超出上圍欄**,是唯一的異常值——對應箱型圖上方的圓圈(見附圖)。

計算與繪圖的程式碼如下(在 Jupyter 執行):

```python
import numpy as np
import matplotlib.pyplot as plt

# 資料已由小到大排序
data = [13, 15, 16, 16, 19, 20, 20, 21, 22, 22, 25, 25, 25, 25, 30,
        33, 33, 35, 35, 35, 35, 36, 40, 45, 46, 52, 70]

# 中程數 = (最小值 + 最大值) / 2
midrange = (min(data) + max(data)) / 2

# 四分位數:以中位數把資料切半,各取一半的中位數
n = len(data)                  # 27 筆
lower_half = data[:n//2]       # 前 13 筆
upper_half = data[n//2 + 1:]   # 後 13 筆(跳過中位數本身)
q1 = np.median(lower_half)
q3 = np.median(upper_half)
iqr = q3 - q1

# 經驗法則(1.5 x IQR)定位異常值
lower_fence = q1 - 1.5 * iqr
upper_fence = q3 + 1.5 * iqr
outliers = [x for x in data if x < lower_fence or x > upper_fence]

print('Midrange =', midrange)
print('Q1 =', q1, ', Q3 =', q3, ', IQR =', iqr)
print('Fences =', lower_fence, '~', upper_fence)
print('Outliers =', outliers)

# 箱型圖(課程提供的程式碼)
fig1, ax1 = plt.subplots()
ax1.set_title('Basic Plot')
ax1.boxplot(data)
```

執行輸出:

```
Midrange = 41.5
Q1 = 20.0 , Q3 = 35.0 , IQR = 15.0
Fences = -2.5 ~ 57.5
Outliers = [70]
```

反思:這幾個衡量方法放在一起看,比任何單一數字都有用。中程數(41.5)完全由最大和最小值決定,一個 70 歲的客戶就把它拉到離真實客群很遠的位置,參考價值最低。IQR 描述的是「中間 50% 客戶」的年齡範圍(20 到 35 歲),不受極端值影響,比全距更能代表主力客群。經驗法則則給了一個客觀標準來判斷「70 歲是罕見客人還是資料錯誤」,不用憑感覺。對這家公司來說,結論是:主力客群集中在 20–35 歲,行銷資源應該投在這個區間;70 歲的紀錄值得先查證再決定是否納入分析。另外,樣本裡有 13、15、16 歲的「客戶」,雖然沒有低於統計上的下圍欄(−2.5),但對酿造公司而言不合理——這說明異常值偵測不能只靠統計規則,還要結合業務常識判斷。

**備註**:matplotlib 箱子下緣畫在 20.5(線性插值),手算法是 20——兩種慣例都對,異常值判定相同;有人問就這樣答。

## 5. 3.1 ML 思維模式:釀酒業七步驟例子

(課文範例 = 預測每天銷售額;此擬答換到生產端,七步驟句式仿課文)

**例子:預測每一批啤酒的發酵品質是否達標**

**步驟 1:設定業務/研究目標**
在發酵完成之前,提早預測這一批啤酒的品質是否達標,減少整批報廢的損失。

**步驟 2:提出假設**
發酵過程中的溫度曲線是預測最終品質的一個有價值的輸入/信號。

**步驟 3:收集數據**
收集過去每一批次的發酵溫度紀錄、糖度變化,以及該批次最終的品質檢驗結果(達標/不達標)。

**步驟 4:驗證假設**
用這些歷史批次資料訓練一個分類模型,再用模型沒見過的批次進行測試。

**步驟 5:評估結果**
這個模型比現行做法(發酵結束後才抽檢)更早、更準地攔截問題批次嗎?誤判率是否在可接受範圍?

**步驟 6:得出結論**
我們應該(不應該)把這個模型放進產線,原因是:能在發酵中途就預警、每年可減少 X 批報廢,但對新配方的批次準確率還不穩定。

**步驟 7:優化假設並重複過程**
酵母菌株與原料批次可能也是有價值的輸入/信號,加入這些屬性後重新訓練、再次驗證。

這個例子和課文的銷售預測互補:銷售預測面向市場端,品質預測面向生產端,但兩者遵循同一套「目標 → 假設 → 資料 → 驗證 → 評估 → 結論 → 迭代」的試錯循環,也呼應了本節說機器學習是一門「試錯」科學的觀點。

### Q1 結果解讀(自用理解,也可摘要進回答)

### Q2 評論框擬答(可直接貼)

> 我在 Jupyter 實際跑了這段代碼並印出樹的結構,發現模型只學到一條規則:X1 <= 0.5 判 0、否則判 1,X2 完全沒有被使用。原因是訓練資料中 X1 單獨就能完美分開兩類(類 0 的 X1 都不超過 0.4,類 1 的都不低於 0.6),決策樹自然選擇最省力的一刀。順帶一提,(0.6, 0.75) 實際輸出是 1 而不是頁面列的 0,這與原始規則(X1>0.5 且 X2>0.5 時 Y=1)一致。
>
> 由此我嘗試從「改變潛在模式與資料」入手提高決策樹的表現:
> 1. **補齊特徵空間的覆蓋**:原資料完全沒有「X1<0.5 且 X2>0.5」象限的樣本,模型在這個區域只能外推。補上這個象限的訓練點(並依規則給標籤)後,樹才有機會學出同時使用 X1 與 X2 的結構,更接近原本設定的三條規則。
> 2. **在決策邊界附近加密樣本**:現在 0.4 到 0.6 之間是空的,分裂閾值 0.5 只是中點的偶然。若規則邊界就是 0.5,在 0.45–0.55 附近補樣本能讓學到的閾值更貼近真實邊界。
> 3. **把潛在模式改成真正依賴兩個特徵**(例如 XOR 型:X1、X2 恰好一個大於 0.5 時 Y=1)再重訓,樹深度會增加、需要的樣本量也明顯變多——可以直觀看到模式複雜度、資料量與樹結構之間的關係。
> 4. **加入少量雜訊並控制 max_depth**,配合 train/test 切分評估:單看訓練準確率會被完美分裂騙到,泛化表現才是衡量「性能提高」的依據。
