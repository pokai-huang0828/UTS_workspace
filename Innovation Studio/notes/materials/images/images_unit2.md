## 5. 要不要用區塊鏈?流程圖 — `files/14041321`

- 盤點:第 89 列,`M352284#10`,alt:「Example flowchart used to determine whether a blockchain is the appropriate technical solution to solve a problem.」
- 檔名 `7.13 Diagrams translated.png`,PNG,8000×3875,376,564 bytes(檔名的 translated = 課程把原英文圖加上中文)
- 類型:**diagram**(流程圖 flowchart)
- 位置:#10「2.8 圖示」→「示例」段落第一張。頁面說明:這張流程圖用來判斷區塊鏈是不是解決某問題的合適技術;改編自 Wüst & Gervais (2018), "Do you need a blockchain?", 2018 Crypto Valley Conference on Blockchain Technology (CVCBT), IEEE。
- 要說明的概念:**有既定語義的標準圖示**(菱形 = 判斷、方框 = 結果、箭頭上標 Yes/No)怎麼把一套決策邏輯講清楚。

**圖中文字(完整)**

判斷菱形(中英對照,中文原為簡體):
1. 是否需要儲存狀態?/ Do you need to store state?
2. 是否存在多個寫入者?/ Are there multiple writers?
3. 是否可以使用始終在線的可信第三方 / Can you use an always online TTP?
4. 是否所有寫入者均已知?/ Are all writers known?
5. 是否所有寫入者都值得信任?/ Are all writers trusted?
6. Is public verifiability required? / 是否需要公開可驗證性?

結果方框:
- 無許可區塊鏈 / Permissionless blockchain
- 公有許可區塊鏈 / Public permissioned blockchain
- 私有許可區塊鏈 / Private permission blockchain(原圖就寫 permission,少了 ed)
- 不要使用區塊鏈 / Don't use blockchain

**流程(依箭頭)**

| 判斷 | Yes → | No → |
|---|---|---|
| 1 需要儲存狀態? | 2 | 不要用區塊鏈 |
| 2 有多個寫入者? | 3 | 不要用區塊鏈 |
| 3 能用一直在線的可信第三方(TTP, Trusted Third Party)? | 不要用區塊鏈 | 4 |
| 4 所有寫入者都已知? | 5 | 無許可區塊鏈 |
| 5 所有寫入者都可信? | 不要用區塊鏈 | 6 |
| 6 需要公開可驗證? | 公有許可區塊鏈 | 私有許可區塊鏈 |

版面:4 個菱形由左到右排在上排,第 5、6 個在第 4 個下方往右排;所有「不要用區塊鏈」的線匯到底部一條橫線,指向右下角方框。

## 13. Bagging 與 Boosting 對照圖 — `files/14041223`

- 盤點:第 97 列,`M352284#18`,alt:「Bagging and boosting: explaining below.」
- 檔名 `2.2.4 Bagging and Boosting.svg`,SVG,46,093 bytes
- 類型:**diagram**(概念示意圖)
- 位置:#18「2.13 集成(Ensemble)」→ 講完「各種集成方法的差別在:怎麼重抽樣資料、怎麼用抽出的副本建基礎預測器(base predictor)、怎麼把預測器組成委員會」之後放這張;圖下方註明「改編自:Bagging and Boosting | Medium」與「*parallel: 平行的;sequential:連續的」,接著才是 Bagging 與 Boosting 的文字說明。
- 要說明的概念:Bagging 是**平行**、各自獨立訓練;Boosting 是**依序**、每一輪根據上一輪的結果調整樣本權重。

**圖中文字(完整)**:Bagging、parallel、Boosting、sequential、…(兩邊各有一個省略號)。其餘都是圖形。

**結構**

- 左半(藍底)Bagging,標籤框 `parallel`:一條線分岔成 3 支箭頭,各指向一個圓(重抽樣後的資料副本,裡面是大小一樣的深藍與橘色小點),每個圓再 → 一個白色圓形的「模型」圖示(小流程圖符號)。第 2 與第 3 組之間有「…」表示還有更多組。三組彼此沒有連線 = 互相獨立、可同時做。
- 右半(青綠底)Boosting,標籤框 `sequential`:第一個圓(資料)→ 模型;模型拉一條箭頭回到下一個圓(下一輪資料)→ 模型 →「…」→ 最後一個圓 → 模型。圓裡的點**大小不一**,代表每筆樣本的權重不同(對應頁面文字:每一輪抽帶權重的樣本,權重依模型預測的難易度調整)。

## 20. 分群方法分類樹 — `files/14041247`

- 盤點:第 104 列,`M352284#6`,無 alt
- 檔名 `Clustering_translated.png`,PNG,5000×2813,319,822 bytes
- 類型:**diagram**(樹狀分類圖)

- 要說明的概念:分群(clustering;課程用語「聚類」)演算法的家族分類。

**圖中文字(完整,原為簡體)與樹狀結構**

```
聚類(Clustering)
├─ 層次聚類(hierarchical)
│   ├─ 凝聚式(agglomerative,由下往上合併)
│   └─ 分裂式(divisive,由上往下切分)
│        └─(兩者共用)→ 單鏈接 / 全鏈接 / 平均鏈接
│   代表演算法(深藍框):Birch, cure, rock, chameleon
└─ 劃分聚類(partitional)
    ├─ 基於距離 → 誤差平方和
    ├─ 基於模型 ┐
    └─ 基於密度 ┘→ 概率模型
    代表演算法(深藍框):K-means, PAM, CLARS, CLSRSNS, FCM, EM, DBSCAN, CLIQUE
```

補充(我加的,不是圖上的字):
- 單鏈接/全鏈接/平均鏈接 = single / complete / average linkage,是層次分群算「兩群距離」的三種方式(台灣常譯「單一連結/完全連結/平均連結」)。
- 圖上的「CLARS」「CLSRSNS」看起來是 CLARA、CLARANS 的拼字錯誤(頁面文字清單寫的是 CLARANS)。PAM = Partitioning Around Medoids(就是 k-medoids);FCM = Fuzzy C-Means(模糊分群,屬軟分群);EM = Expectation-Maximization。
- 「基於模型」和「基於密度」兩條線匯到同一個「概率模型」方框,這是原圖的畫法;嚴格說 DBSCAN(密度式)不是機率模型,讀圖時不要過度解讀。
