## 1. 完整清單(繁體)

**用途**:用這份清單,幫你寫出表述規範的技術研究問題(research question)。

- [ ] **非本領域的人也看得懂**
  - [ ] 不用專業術語(jargon)
  - [ ] 不需要大量背景資訊就能理解
- [ ] **判斷得出問題什麼時候算「回答了」**
  - [ ] 能明確判斷研究該在什麼時候停
  - [ ] 答案可以被驗證
- [ ] **問題回答之後,能提供達成目標所需的知識**
  - [ ] 涵蓋關鍵而且必要的知識
  - [ ] 確實指向技術目標(technical objective)
- [ ] **想得出用什麼方法來回答這個問題**
  - [ ] 不只是把技術目標換句話說
  - [ ] 答案不是輕易就能得到

> 結構:4 個大項,每個大項 2 個細項,共 8 個勾選點。

## 2. 白話解讀(每一項在擋什麼錯)

| 大項 | 它在擋的常見錯誤 | 自我檢查問法 |
|---|---|---|
| 非本領域的人也看得懂 | 問題寫滿縮寫、模型名稱,只有寫的人看得懂 | 念給沒學過資料分析的家人聽,他能說出「你要查清楚什麼」嗎? |
| 判斷得出何時回答了 | 問題太開放(例如「怎樣最好?」),永遠做不完 | 有沒有一個「看到這個結果就可以停」的條件?答案能被別人重做驗證嗎? |
| 回答後能提供達成目標所需的知識 | 問了一個有趣但和技術目標無關的問題 | 回答了它,技術目標就更接近完成嗎?缺了它,技術目標會卡住嗎? |
| 想得出回答的方法 | ①只是把技術目標換句話說(「能不能做到 X?」);②答案查一下就有(不需要研究) | 能不能寫出「用什麼數據、做什麼實驗/分析來回答」?答案是現在還不知道的嗎? |

課程頁對「研究問題」的定義(1.13、1.15):**研究開始時還不知道答案,研究完成後能回答的問題**。研究問題就是「知識目標」;它由技術目標驅動,技術目標又由用戶目標驅動(見單元一 1.15 的研發目標層次圖)。

## 3. 範例(我自己舉的,不是課程原文)

情境:課程案例研究「出租車調度中的乘客需求分析」那一類專案。

- ✗「機器學習能不能改善出租車調度?」→ 只是把技術目標換句話說;什麼時候算回答也說不清。
- ✗「LSTM 和 Transformer 在時空序列上的歸納偏置差異為何?」→ 術語太多,而且不一定是達成目標必需的知識。
- ✓「用過去 4 週每小時的上車紀錄,加上天氣與假日資料,預測未來 1 小時各區叫車量,誤差(MAPE)能不能低於現行人工估計的一半?」→ 外行看得懂大意;有停止條件(MAPE 門檻);答案現在不知道;回答後直接告訴我們「需求預測模組做不做得起來」。

## 4. 這份資料在課程哪裡用得到

- **單元一 1.15.1 頁**:頁面放了這份 PDF,緊接著一個「試試看」互動活動(LTI iframe),要你用清單改寫候選研究問題。
- **單元一 1.13 / 1.15**:1.13 說研究問題是研發的關鍵;1.15 講三類目標(用戶目標 → 技術目標 → 知識目標/研究問題)的層次。
- **AT2 數據分析專案計畫與設計(30%)**:範本要寫「業務目標 Business objectives」和「分析目標和任務 Analytical goals and tasks」(每個業務目標對 1–2 個分析目標,每個分析目標再拆 1–2 個任務)。把分析目標寫成研究問題時,逐條過這份清單;尤其「何時算回答」要對應到「實驗與評估方法」一節的指標與基準。
- **AT2 第 2 部分簡報**:聽眾要假設有非技術的利害關係人 → 第一大項「非本領域人員也能理解」直接適用。
- **AT3 專案分析報告(40%)**:「項目目的和目標」要寫已經達成的目標,前後要和 AT2 一致;研究問題若在 AT2 就寫得可驗證,AT3 才能清楚交代「回答了沒有、怎麼驗證的」。
