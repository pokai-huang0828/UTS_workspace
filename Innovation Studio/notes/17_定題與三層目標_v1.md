## 一頁版
- **題目**:新房東上架定位助手 —— 看懂你的房在雪梨、墨爾本同類 Airbnb 裡站在哪裡。
- **專案目標**:用雪梨、墨爾本 Airbnb 目前房源和 2024 年以來的評論,做競品定位工具:讓準備入行的新房東看掛牌價在同類排第幾、缺哪些設施,照自己的假設試算低/中/高收入,附州規則提醒。
- **業務目標**(要幫誰解決什麼):準備上架的新房東想知道「對手是誰、我的價格算便宜還是貴」;已有房的人想知道「拿來做短租大概能收多少、多久回本」;兩種人都想先知道州規則有哪些要注意。
- **分析目標**(要回答的可量化問題):同類房源找不找得到、掛牌價排第幾;模型估的行情比「同類中位數」準多少;在使用者的假設下收入落在哪個區間。
- **任務**(要做的事):整理資料、建同類組、算分位、比較基準與樹模型、做 AI 解釋卡、做情境試算與規則提醒。
- **「新上架房源」**:有價樣本裡,第一則評論日期落在資料抓取日往前 12 個月內(含起點當天)的房源。

## 2. 三層目標 v1(業務 → 分析 → 任務)

**BO1 準備上架的新房東:「我的對手是誰?我的掛牌價算便宜還是貴?缺什麼?」**(主線,方案 A)
- AG1.1 輸入一間房,找得到多少間同類房源?它的掛牌價在同類裡排第幾分位?
- AG1.2 用樹模型估「同類行情價」,比「同區同格局中位數」基準準多少?(**唯一的實驗主線**)

**BO2 已有房的屋主:「拿來做短租、再添一些設備,大概收多少、多久回本?」**(B① 掛在這裡)

- AG3.1 每間輸入房源能不能都顯示對應的州規則提醒?每區有多少同類短租房源?

## 3. 「新上架房源」代理定義

**提案定義(待投票;照這個就能重算)**
- 樣本:有價樣本 = `room_type` = Entire home/apt、`bedrooms` 為 1 或 2、`accommodates` 2–4、`minimum_nights` 1–7,且 `price` 非空(雪梨 6,639、墨爾本 8,223)。
- 基準日:該城 listings 的 `last_scraped` 最大值(雪梨 2026-09-17、墨爾本 2026-09-18;批次標籤是 2026-09-16)。
- 最近 12 個月:起點 = 基準日往前推 12 個月的同一天(雪梨 2025-09-17、墨爾本 2025-09-18);`first_review` ≥ 起點就算,**含起點當天**(落在起點當天的有 4 / 4 筆);終點就是基準日(晚於基準日的 0 筆)。日期用 YYYY-MM-DD 字串比較。
- 結果:雪梨 **2,028**、墨爾本 **2,056**,和品質檢查 JSON 的 `first_review_within_12m_before_batch` 一致(程式 assert 通過)。

**納入 / 排除規則**

| 情況 | 處理 | 理由 |
|---|---|---|
| 沒有任何評論(588 / 816 筆) | **不算新上架,也不算舊房源**,另列「未評論」組;系統裡照樣當競品顯示 | 首評、末評都空,分不出「太新還沒評論」還是「不活躍」;算進新上架會混入可能長期沒人訂的房,算成舊的又不對。另列分母最誠實,也能做敏感度 |
| 日曆全關(`availability_365` = 0) | 排除 | 已經不接客,不是新房東的對手;今天有價樣本裡 0 筆,新上架與未評論組也都 0 筆,所以目前不影響筆數 |
| 多房源房東(`calculated_host_listings_count` ≥ 2) | 主定義**保留** | 它們就是新房東的真實對手;新上架裡房東在本城有 ≥ 5 間的有 969 / 968 筆。要看「新手房東」時改用下面的子集 |

**「新上架房源」≠「新手房東」**
- 新上架講的是**房源**最近才拿到第一則評論;新手房東講的是**人**剛開始當房東。新上架 2,028 / 2,056 筆只來自 1,239 / 1,250 個 `host_id`,很多是老房東再上新房。
- **反證(要在今晚說明)**:16 原本(L114、L390)寫「資料裡沒有房東什麼時候開始當房東的欄」。今天查到 `hosts_time_as_host_years`、`hosts_time_as_host_months` 兩欄在有價樣本裡全部有值(6,639 / 8,223)。年資(月)= years × 12 + months。⚠️欄義是照欄名推斷,官方欄位說明還沒查,算到哪一天為止也還沒確認。獨立核對(`raw/aim_review_2026-11-11.md` L22–30):數字重算吻合;年資欄偏可用但要加註 —— 跟首評時間矛盾的,有價樣本雪梨 0.64%、墨爾本 1.78%;同一房東多筆房源的年資 100% 一致;`months` 是 0–11 的餘數,不是總月數。確認欄義前不放進提案定義。
- **建議子集「新手房東代理」**:新上架 + 房東在本城只有這一間(`calculated_host_listings_count` = 1)+ 房東年資 ≤ 12 個月 → 雪梨 **444**、墨爾本 **514**(**今天已算**)。只要求「只有這一間」不看年資:688 / 713(今天已算)。

**敏感度(今天已算;「年資」條件跟著窗口走 = 年資 ≤ 6 / 12 / 18 個月)**

| 窗口 | 起點(雪 / 墨) | 新上架(雪 / 墨) | 其中只有這一間 | 其中房東年資 ≤ 窗口 | 只有這一間 + 年資 ≤ 窗口 |
|---|---|---|---|---|---|
| 6 個月 | 2026-03-17 / 2026-03-18 | 994 / 975 | 303 / 309 | 282 / 354 | 190 / 220 |
| **12 個月** | 2025-09-17 / 2025-09-18 | **2,028 / 2,056** | 688 / 713 | 723 / 857 | **444 / 514** |
| 18 個月 | 2025-03-17 / 2025-03-18 | 2,535 / 2,681 | 851 / 900 | 1,028 / 1,223 | 562 / 664 |

未評論組(不在上表):房東年資 ≤ 12 個月的有 227 / 242 筆,其中只有這一間的 118 / 144 筆 —— 未評論組裡確實有新房東,這是排除它的代價。

**已知偏誤**(偏誤 → 不要這樣說 → 改這樣說)
1. 首評晚於上架:上架後要等第一個客人住完留評論 → 「這些房源都是最近 12 個月上架的」 → 「首評在最近 12 個月內的房源,用來代理新上架;實際上架日可能更早」。
2. 存活偏差:只看得到 2026-09 還在架上的,做不下去而下架的新房源看不到 → 「新上架房源的價格行情就是這樣」 → 「目前仍在架、首評在最近 12 個月內的房源的掛牌價分布」。
3. 排除未評論:最新、還沒人訂的房源被拿掉 → 「新房東一般定價在某區間」 → 「已拿到第一則評論的新上架房源的掛牌價區間;未評論的另列」。
4. 多房源房東混入:主定義裡很多是老房東的新房 → 「新房東的定價行為」 → 「新上架房源的定價;單一房源、新年資的子集另外列」。
5. 掛牌價不是成交價 → 「市場成交價」 → 「掛牌價(抓取當下的報價)」。
